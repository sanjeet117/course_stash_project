GIT STASH WORKFLOW - COMMAND LOG
================================

Project:
Course Management Project

Purpose:
This file records the Git stash workflow demonstrated during the assignment.


1. START FEATURE DEVELOPMENT
----------------------------

Branch used:

feature/add-course

Command:

git switch feature/add-course

Feature implementation was started in course.py.

The course_duration() feature was intentionally left as unfinished work.


2. CHECK UNCOMMITTED CHANGES
-----------------------------

Command:

git status

Key result:

course.py was modified and the changes were not committed.


3. SAVE UNFINISHED WORK USING STASH
------------------------------------

Command:

git stash

Purpose:

Temporarily save unfinished uncommitted changes and make the working directory clean.

Key result:

The unfinished course duration changes were stored in the stash.


4. STASH LIST
-------------

Command:

git stash list

Key result:

stash@{0}: WIP on feature/add-course: 61fc29a added course duration feature

Purpose:

Displays the stash entries currently stored locally.


5. STASH SHOW
-------------

Command:

git stash show

Purpose:

Displays a summary of the changes stored in the stash.

Key result:

The stash contained changes to course.py.


6. STASH SHOW -P
----------------

Command:

git stash show -p

Purpose:

Displays the detailed code differences stored in the stash.

Key result:

The course duration feature changes were visible in the stash diff.


7. SWITCH TO URGENT FIX BRANCH
------------------------------

Command:

git switch main

Then:

git switch -c hotfix/course-display

Purpose:

Switch to another branch to handle an urgent fix while the feature work remained safely stored in the stash.


8. URGENT FIX
-------------

The course instructor display was fixed on the hotfix/course-display branch.

Commands:

git add course.py

git commit -m "Fix course instructor display"

Key result:

The urgent fix was committed successfully.


9. RETURN TO FEATURE BRANCH
----------------------------

Command:

git switch feature/add-course

Purpose:

Return to the original feature branch after completing the urgent fix.


10. APPLY STASH
--------------

Command:

git stash apply

Purpose:

Restore the unfinished feature changes from the stash into the working directory.

Key result:

The course duration changes were restored.

Important:

git stash apply restores the changes but keeps the stash entry in the stash list.


11. CHECK STASH AFTER APPLY
---------------------------

Command:

git stash list

Key result:

The stash entry was still available.

This demonstrates that git stash apply does NOT remove the stash.


12. STASH POP
------------

Command:

git stash pop

Purpose:

Restore the stashed changes and remove the stash entry after successful application.

Key result:

The changes were restored and the stash entry was removed.


13. STASH DROP
--------------

Command:

git stash drop stash@{0}

Purpose:

Remove a specific stash entry from the stash list.

Note:

A separate stash entry was used for demonstrating git stash drop after the main stash workflow.


14. APPLY VS POP
----------------

git stash apply:

- Restores the stashed changes.
- Keeps the stash entry.
- The stash can be reused later.

git stash pop:

- Restores the stashed changes.
- Removes the stash entry after successful application.

Simple difference:

Apply = Restore changes + Keep stash

Pop = Restore changes + Remove stash


15. COMPLETE COMMAND SEQUENCE
-----------------------------

The stash workflow demonstrated in this assignment was:

git stash

git stash list

git stash show

git stash show -p

git stash apply

git stash pop

git stash drop stash@{0}


16. REAL DEVELOPMENT TEAM USE CASE
-----------------------------------

Git stash is useful when a developer is working on an incomplete feature but suddenly needs to switch to another task.

For example:

Developer is working on Feature A.
Feature A is incomplete.
An urgent production bug appears.
The developer uses git stash.
The developer switches to a hotfix branch.
The urgent bug is fixed and committed.
The developer returns to Feature A.
The stashed changes are restored.
Feature A development continues.


17. IMPORTANT CONCEPT
---------------------

Completed work:

git commit

Temporary unfinished work:

git stash

The main purpose of Git stash is to temporarily save unfinished changes without creating an unnecessary commit.
